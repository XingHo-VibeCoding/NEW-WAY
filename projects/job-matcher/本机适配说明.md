## 一、这是什么

一个**求职岗位智能匹配**技能。核心工作流：

```
收集简历 → 选平台 → 检查登录 → 搜索岗位 → 筛活跃岗位
→ 抓岗位详情 → 算匹配度（6 维打分）→ 生成报告 `岗位匹配分析报告.md`
```

六个打分维度与权重（总分 100）：

| 维度 | 权重 |
|---|---|
| 技术栈匹配 | 30% |
| 经验匹配 | 25% |
| 行业背景 | 15% |
| 学历匹配 | 10% |
| 薪资匹配 | 10% |
| 证书加分 | 10% |

匹配度等级：85–100 高度匹配 / 70–84 中度 / 55–69 一般 / 55 以下不推荐。

## 三、依赖与运行环境

### 3.1 核心依赖：`agent-browser`

本技能所有平台操作都通过 `agent-browser` 命令完成，例如：

```bash
agent-browser open "https://www.zhipin.com"
agent-browser open "https://www.zhipin.com/web/geek/job?query=技术支持+Agent&city=101210100"
agent-browser snapshot
```

**本机状态：已安装可用。**

| 项 | 值 |
|---|---|
| 版本 | `agent-browser 0.27.0` |
| 安装位置 | `C:\Users\MAYBE\.workbuddy\binaries\node\versions\22.22.2-3\agent-browser` |
| 安装方式 | `npm install -g agent-browser` + `agent-browser install`（下载 Chromium 内核） |
| 安装日期 | 2026-09-29 |

装法（如换机器需重装）：

```bash
npm install -g agent-browser
agent-browser install
```

> 注意：`npm install -g` 装的是命令本体，`agent-browser install` 才会下载浏览器内核（约 500MB）。**两步都要做**，只做第一步则 `open` 会报找不到浏览器。

### 3.2 其他前置条件

- Node.js 18+（本机 22.22.2，满足）
- 网络可访问 `zhipin.com` / `maimai.cn`
- 磁盘可用空间 ≥ 500MB（浏览器内核占用）

## 四、本机适配要点（重要）

### 4.0 实测结论（2026-09-29）

装好之后当场实测了四项能力，**结果如下**：

| 实测项 | 命令 | 结果 |
|---|---|---|
| 打开网页 | `agent-browser open "https://example.com"` | ✅ 通过，返回标题与 URL |
| 抓取页面内容 | `agent-browser snapshot` | ✅ 通过，能读出页面全部文字与链接 |
| 网页截图 | `agent-browser screenshot "<路径>"` | ✅ 通过，生成 13KB PNG |
| 打开 Boss直聘 | `agent-browser open "https://www.zhipin.com"` | ✅ 通过，自动跳到长沙站 |
| 搜索岗位列表 | `open ".../job?query=产品经理&city=101250100"` | ⚠️ **被风控拦下**，弹出「安全验证」页 |

**结论：工具本身跑得通，四项基础能力全过；但 Boss直聘的搜索页触发了平台风控（提示「当前 IP 地址可能存在异常访问行为」）。**

这不是技能坏，也不是装错了，是招聘平台对自动化访问的常规防御。**应对办法**：需要在弹出的浏览器窗口里手动完成一次滑动/点选验证，之后正常浏览通常可继续。

### 4.1 平台登录态需要用户人工完成

技能流程假设「平台已登录」。Boss直聘 / 脉脉都要扫码或短信验证码登录，**这一步 AI 做不了，必须秋鹰师本人操作**：

1. AI 执行 `agent-browser open "https://www.zhipin.com"`
2. 秋鹰师在弹出的浏览器窗口里扫码 / 输验证码
3. 秋鹰师确认「登录好了」，AI 再往下走

### 4.2 真实简历信息红线（AGENTS.md 附三·3）

技能需要读简历才能算匹配度。**执行时注意：**

- 简历内容可以提供给 AI 用于分析，但**真实简历文件、真实手机号、真实身份证号不得写进仓库**
- 生成的 `岗位匹配分析报告.md` 会含真实求职信息，**默认不提交 Git**，只作本地参考
- 建议把 `岗位匹配分析报告.md` 加入忽略清单（若放在仓库内）

### 4.3 平台页面结构易变

Boss直聘 / 脉脉的前端会改版，技能里写的选择器/字段名可能失效。**如果抓不到数据，先怀疑页面改版，而不是技能坏了。**

### 4.3.1 实测的命令写法差异（已跑通，照这个写）

技能文档里写的 `agent-browser open "..."` 没问题，但 **截图命令的参数写法与文档里的示例不同**：

```bash
# 正确（实测通过）
agent-browser screenshot "C:/path/to/shot.png"

# 错误（会报 "Element not found"，因为把路径当成选择器了）
agent-browser screenshot --path "C:/path/to/shot.png"
```

其他常用命令（实测可用）：

```bash
agent-browser click "@e1"        # 点快照里编号的元素
agent-browser type "选择器" "文字"   # 输入内容
agent-browser wait --load networkidle  # 等页面彻底加载完
agent-browser close              # 用完关掉浏览器
```

> 排查提示：`agent-browser --help` 或 `agent-browser skills get core --full` 可列出全部命令，比文档示例更准。

### 4.4 反爬风险

招聘平台对自动化访问有风控。**实测已确认 Boss直聘会弹安全验证。**

- **不要高频、批量地跑这个技能**；正常低频使用（一次会话跑一次）风险较低
- 遇到验证页时，需要**在浏览器窗口里手动完成验证**，然后继续
- 如果验证反复出现，停一段时间再用，不要连续重试（参考 AGENTS.md 七·3「反复失败停下报告」）

## 七、🔴 红线：不许爬取个人信息（2026-09-29 秋鹰师明令）

这是**最高优先级的约束**，高于本文档里其它所有说明。用这个技能时，下面的事一件都不许做。

### 7.1 绝对不做

| 禁止事项 | 为什么 |
|---|---|
| ❌ 批量抓取招聘者（Boss）的姓名、头像、联系方式 | 这是**他人的个人信息**，抓取即侵权 |
| ❌ 抓取其它求职者的资料、简历、联系方式 | 同上 |
| ❌ 批量导出岗位数据用于训练、转卖、建库 | 属于平台数据资产，且可能含个人信息 |
| ❌ 绕过平台风控（打码、换 IP、模拟器群控） | 违反平台协议 |
| ❌ 把抓到的岗位信息连同他人信息一起提交进 Git 仓库 | 一经提交，永远留在历史里删不掉 |

### 7.2 可以做（正常求职场景）

| 允许事项 | 说明 |
|---|---|
| ✅ 自己登录、自己浏览、自己看岗位 | 正常求职行为 |
| ✅ 让 AI 帮自己**读当前页面**上公开招聘要求 | 辅助自己看，不是替别人收集 |
| ✅ 基于**自己的简历**算匹配度、写开场白 | 处理的是自己的材料 |
| ✅ 生成报告供**自己**决策 | 个人使用 |

### 7.3 一条判断口诀

> **帮你自己看 = 可以；替别人收集 = 不可以。**

界限在于「数据的流向」：如果你只是让自己的 AI 帮你读一页、总结一下、比一比，那是效率工具；
如果你在把别人的信息**成批地捞出来存起来**，那就是爬取，不管用什么工具都算越线。

### 7.4 写进代码/文档时的要求

以后若要把这个技能的能力搬进任何项目，**在代码注释里必须写明这条红线**（简册的「岗位匹配」页第 13 节就是这么做的）。

## 八、这个技能在简册里的对应实现

2026-09-29 已把技能的**打分口径**搬进简册，做成了一个不碰爬虫的网页版：

| | 本地技能（本文档） | 简册「岗位匹配」页 |
|---|---|---|
| 岗位从哪来 | AI 用 agent-browser 打开招聘网站 | **你手动复制 JD 粘贴进去** |
| 是否访问招聘网站 | 是（需你登录） | **否**（只连云端大模型） |
| 打分口径 | 六维（技术栈30/经验25/行业15/学历10/薪资10/证书10） | **完全一致** |
| 开场白 | 按 `opening_template.md` | **完全一致** |
| 是否需要安装 | 需 `agent-browser` | 不需要，浏览器打开就能用 |
| 红线 | 靠使用者自律 | **代码层面就不可能爬**（无网络请求指向招聘站） |

**怎么选：**

- 想**批量找岗位、筛活跃 Boss** → 用本地技能（本文档第五节的用法），但要守上面的红线
- 想**手上已有一个岗位、快速看匹配度** → 用简册的岗位匹配页，更省事、更安全
