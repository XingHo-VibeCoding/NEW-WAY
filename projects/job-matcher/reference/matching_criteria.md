# 岗位匹配度评分标准

## 评分维度详解

### 1. 技术栈匹配（权重：30%）

**评分标准**：
- JD要求的技术栈与用户技能的重合度
- 核心技能匹配度 vs 加分技能匹配度

**评分细则**：
- 核心技能100%匹配：25-30分
- 核心技能80%匹配：20-24分
- 核心技能60%匹配：15-19分
- 核心技能40%匹配：10-14分
- 核心技能20%匹配：5-9分
- 核心技能不匹配：0-4分

**示例**：
- JD要求：Python、Agent开发、RAG
- 用户技能：Python、Agent开发、RAG、MCP → 28分（高度匹配）
- 用户技能：Java、微服务、MySQL → 5分（不匹配）

### 2. 经验匹配（权重：25%）

**评分标准**：
- 工作年限是否满足
- 项目经验是否匹配
- 行业经验是否相关

**评分细则**：
- 年限满足 + 项目经验高度匹配：22-25分
- 年限满足 + 项目经验中度匹配：18-21分
- 年限满足 + 项目经验低度匹配：12-17分
- 年限不满足但项目经验匹配：8-11分
- 年限和项目经验都不匹配：0-7分

**示例**：
- JD要求：5年以上，有大模型项目经验
- 用户：5年经验，主导过AI Coding助手项目 → 24分
- 用户：3年经验，无大模型项目 → 8分

### 3. 行业背景（权重：15%）

**评分标准**：
- 用户过往行业经验与目标公司行业的关联度

**评分细则**：
- 同行业经验：13-15分
- 相关行业经验：9-12分
- 行业跨度较大：5-8分
- 完全不同行业：0-4分

**示例**：
- 目标公司：阿里云（云计算）
- 用户：酷家乐（SaaS平台）→ 12分（相关行业）
- 用户：银行 → 6分（行业跨度较大）

### 4. 学历匹配（权重：10%）

**评分标准**：
- 学历要求是否满足

**评分细则**：
- 学历超出要求：10分
- 学历正好满足：8-9分
- 学历低于要求但有相关经验：5-7分
- 学历不满足：0-4分

**示例**：
- JD要求：本科及以上
- 用户：本科 → 9分
- 用户：硕士 → 10分
- 用户：大专 → 6分（但可能被HR筛选掉）

### 5. 薪资匹配（权重：10%）

**评分标准**：
- 岗位薪资范围与用户期望的匹配度

**评分细则**：
- 薪资范围完全符合期望：10分
- 薪资范围大部分符合期望：7-9分
- 薪资范围部分符合期望：4-6分
- 薪资范围不符合期望：0-3分

**示例**：
- 岗位薪资：30-50K
- 用户期望：35-45K → 9分（高度匹配）
- 用户期望：20-30K → 6分（偏低）
- 用户期望：60K以上 → 4分（偏高）

### 6. 证书加分（权重：10%）

**评分标准**：
- 专业认证是否与岗位要求匹配

**评分细则**：
- 证书高度匹配且权威：10分
- 证书相关但不完全匹配：6-9分
- 有证书但与岗位无关：3-5分
- 无相关证书：0-2分

**示例**：
- 岗位：阿里云相关岗位
- 用户：阿里云大模型ACP → 10分（高度匹配）
- 用户：AWS认证 → 7分（相关但不完全匹配）
- 用户：无认证 → 2分

## 总分计算

**总分** = 技术栈匹配分 + 经验匹配分 + 行业背景分 + 学历匹配分 + 薪资匹配分 + 证书加分

**匹配度等级**：
- **85-100分**：高度匹配，强烈推荐投递
- **70-84分**：中度匹配，重点关注
- **55-69分**：一般匹配，可以考虑
- **55分以下**：匹配度较低，不推荐

## 特殊情况处理

### 情况1：JD描述过于简单
- 如果JD信息不足，基于岗位名称和公司背景推断要求
- 适当降低评分权重，更多依赖用户判断

### 情况2：用户简历信息不完整
- 如果用户简历信息不足，主动询问补充
- 对于缺失的信息，给予中等评分（如5分）

### 情况3：跨行转型
- 如果用户是跨行转型，重点评估可迁移能力
- 适当降低行业背景维度的权重，提高技术栈和项目经验的权重
