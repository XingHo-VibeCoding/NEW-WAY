### 唯一发现：320px 超窄屏下流水行装不下（**未修，按规矩留到下次**）

**实测数据**（`.exp-row` 内部尺寸）：

| 屏幕宽 | 卡片内可用宽 | 行内固定元素合计 | 结论 |
| --- | --- | --- | --- |
| 360px | 262px | 日期 32 + 金额 82 + 操作 92 + 间距 30 = **236px** | ✅ 够 |
| 375px | 277px | 同上 236px | ✅ 够 |
| **320px** | **222px** | 同上 **236px** | ❌ **超 14px** |

**根因**：行里有三个**不许压缩**的元素 —— 日期列（32px）、金额（82px）、编辑/删除按钮组（92px）。
三者相加 236px 是物理下限；320px 屏幕下卡片只剩 222px，**装不下**。

**为什么今天不修**：
1. 320px 已基本退市（iPhone SE 一代 2016 / 老安卓），主流最低是 360px。
2. 页面整体**没有横向溢出**（外层有保护），只是行内被挤紧。
3. 要修得给操作按钮改成换行或缩字号 —— **属于「按反馈大改版」**，违反今日「今日不做：一口气全改」。

**结论**：登记为**已知限制**，留给下一次专门做窄屏适配时处理。

## 五、技术诊断（修复的依据）

用 Chrome 无头模式生成修复前后的 PDF，再用 PyMuPDF 逐字符量取，**用数据代替印象**：

| 检测项 | 修复前 | 修复后 |
| --- | --- | --- |
| 纸张尺寸 | 216 × 279 mm（**Letter，非 A4**） | **210 × 297 mm（A4）** ✅ |
| 纸面底色 | **深黑底 + 金网格** | 纯白 ✅ |
| 正文（经历内容） | 10.5pt | **11pt** ✅ |
| 辅助文字（公司 / 时间） | **9pt**（合同小字级） | **10pt** ✅ |
| 最浅文字亮度 | — | **127.8 / 255**（最浅的一档，仍在白纸上清晰可读）✅ |
| 浅色（看不见）的文字 | **大量** | **0 条** ✅ |
| 「AI 优化」按钮 | **印在纸上** | 已隐藏 ✅ |
| 量化结果标签 | **空白框（白底白字）** | 红字 + 描边，清晰 ✅ |

**三条根因**（都不是"简陋"，是真 bug）：

1. **黑底印出来**：`body:has(#page-resume.is-active)`（原第 942 行）是 `body + 伪类 + ID` 的复合选择器，**特异性高过** 打印块里的裸 `body`；而且它用 `background-image` 画了金网格，打印块原先只改 `background`、**没管这个属性**。
2. **「AI 优化」按钮被印出来**：隐藏名单里有 `.resume-toolbar`、`.ai-card`，**漏了 `.resume-ai`**。招聘官看到简历上印着「AI 优化」= 明说这份简历是机器写的。
3. **量化结果标签空白框**：打印块把 `color` 改成 `#000`，但**深色底还在** → 黑字落深底 = 看不见。

**修复中自己踩的坑（诚实记录）**：第一次只改了背景没改文字色 → 变成「白底白字」，比修之前更糟。**教训：改暗色主题的打印态，背景与文字必须成对处理，只改一半必翻车。** 第二次改用「同等特异性反打 + 变量在 body 层翻白 + 纸内所有文字钉死颜色兜底」三道保险。
