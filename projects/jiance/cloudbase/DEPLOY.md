## 〇、先把三样东西抄在一张纸上

部署前你会拿到三个值，后面每一步都要用，建议先抄下来（不要写进代码、不要提交）：

| 要点 | 长什么样 | 在哪看 |
|---|---|---|
| **环境 ID**（envId） | 形如 `jiance-3g8xxxx` | 云开发控制台首页左上 / 环境列表 |

> 两个默认域名都**只用于开发测试**：有访问频率限制，浏览器第一次打开可能弹一个安全提示中间页。这是正常的，点继续访问即可。

## 一、部署云函数 `/api/health`

### 目标
浏览器打开 `https://{HTTP访问域名}/api/health` 时，看到：

```json
{"ok":true,"service":"Ledger and Career"}
```

### 步骤

| # | 你在哪操作 | 具体做什么 | 做完应该看到 |
|---|---|---|---|
| 1 | 云开发控制台 | 选中你的环境 | 进入环境总览页 |
| 2 | 左侧菜单 | 点「**云函数**」 | 函数列表（新环境是空的） |
| 3 | 云函数页 | 点「**新建云函数**」 | 弹出新建面板 |
| 4 | 新建面板 | 函数名填 **`health`**（一字不差，建议全小写） | —— |
| 5 | 新建面板 | 运行环境选 **Node.js 18**（有更高 LTS 也行） | —— |
| 6 | 函数编辑器 | **清空**模板代码，把 `projects\cloudbase\functions\health\index.js` 全文粘进去 | 编辑器里只剩我们的代码 |
| 7 | 编辑器 | 点「**保存并安装依赖**」 | 提示部署成功 / 函数状态变「正常」 |
| 8 | 函数**详情页** → 域名管理（或「自定义域名」区） | 点「添加域名」→ 触发路径填 **`/api/health`** → 保存 | 触发路径列表出现 `/api/health` |
| 9 | 同上（另一种入口） | 或走「**HTTP 访问服务**」→ 域名关联资源 → 新建：资源类型＝云函数、函数＝`health`、触发路径＝`/api/health` | 同上 |
| 10 | 浏览器 | 打开 `https://{HTTP访问域名}/api/health` | 见下方「通过长什么样」 |

> 第 8/9 步任选其一即可，不用两个都做。
> 配好后**等 3–5 分钟**生效 —— 文档写明新建 HTTP 服务需要这个时间，别在半分钟后就判定失败。

### 通过长什么样（完成标准的证据）

```json
{"ok":true,"service":"Ledger and Career"}
```

**截图要点**：地址栏要露出来（能看到 `.../api/health`），页面主体是上面那行 JSON。

### 排错对照表

| 你看到的现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| `404 Not Found` / 无法访问此网站 | 路由没生效，或触发路径拼错 | 等满 5 分钟；核对大小写与斜杠：`/api/health` 不是 `/api/health/`、也不是 `/api/Health` |
| 返回的 JSON 外面套着 `statusCode` / `headers` / `body` 三个字段 | 平台把「集成响应」原样吐出来了 | 改用 `index.js` 文件末尾注释里的**备选写法**（直接 `return { ok: true, service: 'Ledger and Career' }`） |
| 502 / FunctionNotReady / 函数状态异常 | 函数没部署成功 | 回函数详情看部署日志；确认第 6 步真的把模板代码**清空**了 |
| 浏览器先弹一个安全提示中间页 | 默认域名的正常行为 | 点继续访问；正式上线才需要备过案的自定义域名 |
| 页面是空白 / 中文乱码 | 编码 | 我们的代码已写死 `charset=utf-8`；若仍异常，回看第 6 步是否粘贴完整 |
| 提示「环境未开通 HTTP 访问服务」 | 全局开关没开 | 「HTTP 访问服务」页顶部把总开关打开 |

### 自检（可选，命令行）

```bash
curl -i "https://{HTTP访问域名}/api/health"
```

看到 `HTTP/2 200`、`content-type: application/json; charset=utf-8`、body 是那行 JSON，即为全通。

## 二、部署前端页面（mock 版）到静态托管

### 先说清楚「前端 mock 版」指什么（v1.12 已废，本节只留作历史口径）

v1.12 之前简册第 2 周的成果是**单个 `index.html`**（TECH_DESIGN 4.1 / 4.2 原拍板：单个文件承载整个应用）。**v1.12 起改为 React + Vite 项目**，前端部署物为 **`projects/jiance/dist/`**（`npm run build` 产物）。

也就是说「构建 mock 版」现在落地为：**`npm run build` 之后把 `projects/jiance/dist/` 里的文件（`index.html` + `favicon.svg` + `icons.svg` + `assets/`）扁平化传到 CloudBase 静态托管的根目录**。

### 步骤

| # | 你在哪操作 | 具体做什么 | 做完应该看到 |
|---|---|---|---|
| 1 | 云开发控制台 → 左侧「静态网站托管」 | 首次进入点「开通」 | 出现「部署 / 上传」入口 |
| 2 | 静态托管页 | 点「上传文件」→ 选中 **`D:\梦空间\index.html`** | 上传进度走完 |
| 3 | 部署列表 | 等状态变成「成功」 | 列表里出现该应用与访问地址 |
| 4 | 基础配置 | 记下**默认域名**；确认「默认首页文档」是 `index.html` | 域名形如 `{envId}-{APPID}.tcloudbaseapp.com` |
| 5 | 电脑浏览器 | 打开默认域名 | 看到简册首页（底牌页） |
| 6 | **手机浏览器** | 打开同一个域名（流量或同一 WiFi 都行） | 同样能打开 → **今天这条完成标准达成** |

**截图要点**：手机/电脑上都要能看清地址栏（`.tcloudbaseapp.com`）+ 页面主体。

### 排错对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开是一串文件目录列表 | 默认首页文档不是 `index.html` | 「基础配置 → 路由配置」里把首页文档设为 `index.html` |
| 打开 404 | 传的是**文件夹**而不是单个文件，或文件名不叫 `index.html` | 重新「上传文件」，只选那一个 `.html` |
| 页面样式像是旧版本 | CDN 缓存（1–3 分钟生效） | 强刷（Ctrl+F5）或等 1–3 分钟再试 |
| 手机上白屏、电脑正常 | 手机浏览器缓存旧版 | 换无痕窗口/换个浏览器打开 |
| 手机上打不开但电脑能开 | 网络 | 手机切 4G/5G 或换个网络再试；默认域名有访问频率限制，短时间内反复刷可能被限 |

### 关于数据：今天**不会**同步

手机上打开的是一个**全新的空账本**，因为它读的是「这台手机自己的浏览器抽屉」。你在电脑上记的账不会跑到手机上 —— 这是本期**预期行为**，不是 bug（数据上云要等第 3 周的表和接口做完）。

## 三、今天**不做**的两件事（照 Day 15 清单）

1. **跨域（CORS）不处理**：页面里用 `fetch('/api/health')` 现在会被浏览器拦下（不是代码写错，是浏览器在保护用户）。
   所以今天验证云函数的方式是「**直接用浏览器开那个地址**」——直接开地址不属于跨域请求，不受影响。
   跨域留到 Day 16 之后和真实接口一起处理。
2. **不建数据库、不写业务接口**：今天只有一个不碰数据的探路石接口。
