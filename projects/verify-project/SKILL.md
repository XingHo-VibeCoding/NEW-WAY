# 简册 · 发布前自检（verify-project）

> 一句话：这是「**发布前的体检单 + 体检仪**」。体检单是这份文档，体检仪是
> `scripts/verify.mjs` —— 它照着单子逐条去查，查完直接告诉你哪条红、为什么红。

## 为什么要有它（和 `jiance-review` 的分工）

| 技能 | 什么时候用 | 看什么 |
|---|---|---|
| `jiance-review`（`projects/skill-review/`） | **动手写代码前 / 写完功能时** | 术语、假数据、无障碍、交互四态这些「人写的东西对不对」 |
| **`verify-project`（本目录）** | **发布 / 提交前** | 机器能判的硬事实：密钥、环境变量、跨域、接口契约、构建产物 |

两者不重叠：前者管「你想得对不对」，后者管「**东西现在到底是不是好的**」。

## 怎么用

```bash
cd D:/梦空间
node projects/verify-project/scripts/verify.mjs
```

**参数**（都可省略）：

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `--explain` | 每条后面多印「怎么查 / 通过标准」 | 想看清判据、或讲解给别人听 |
| `--no-net` | 跳过所有联网项（标 SKIP） | 断网、或只想快速查本地 |
| `--with-write` | 打开「组 H · 重复写入」（会往云端真写一条 0.01 元假账，跑完自己删） | 想验防重复提交是否还有效 |
| `--fast` | 全历史扫描只看最新一个提交 | 只想快速扫一眼（⚠️ 会漏掉老提交里的问题，别用于正式发布） |
| `--groups=A,C` | 只跑指定组 | 排查某一类问题 |

**退出码**：有任何一条 FAIL → 退出码 1（可直接接进别的脚本）；全绿 → 0。

## 怎么读输出

| 记号 | 含义 | 你该做什么 |
|---|---|---|
| `✅ PASS` | 查了，符合通过标准 | 不用管 |
| `❌ FAIL` | 查了，不符合 | **必须处理**，证据行告诉你哪儿不对 |
| `⏭ SKIP` | **没查成**（断网、文件不存在等） | ⚠️ **SKIP 不等于通过**。发布前必须把它变成 PASS（比如联上网重跑） |

🔴 **一条纪律**：报告里出现 SKIP，就不能说「自检通过」—— 那等于体检时有一项没做，
却拿着一张缺项的单子说「全绿」。诚实写法是「通过 X / 失败 Y / **跳过 Z**」。

### 反向验证：证明它**不会虚报通过**（第 3 轮）

**要防的那个坑**：一份永远全绿的报告，可能是「真健康」，也可能是「仪器根本没接电」。
两种情况下报告长得一模一样 —— 所以**必须故意弄坏一项，看它红不红**。

| 步骤 | 做了什么 | 期望 | 实测（2026-10-13） |
|---|---|---|---|
| ① | 干净态跑 | 全绿 | 39 / 39 PASS |
| ② | 在 `projects/jiance/` 放一个文件，里面写一个**编造的密钥形状假串**（`sk-` + 36 位字母） | **恰好 A2 一条变红** | ✅ 只有 A2 FAIL，其余 35 条仍绿；退出码 1 |
| ③ | 删掉该文件，再跑 | 回到全绿 | 39 / 39 PASS |

第 ② 步 A2 的证据行（「它能查出来」就长这样）：

```
❌ FAIL A2 会被提交的文件里无密钥特征串
   证据：命中 1 处：
projects/jiance/__day25_probe.js:11  export const DAY25_PROBE = 'sk-<36 位字母表，本文档里已打码>'
```

> ⚠️ **上面那行是打过码的，不是原始输出。** 为什么必须打码 —— 这里有个自己踩自己的好例子：
> 我一开始把**原始那一行连假串一起**抄进了这份文档。再跑一次时 A2 立刻报红，
> 命中的是 **`projects/verify-project/SKILL.md` 这个文件本身**：
> 这份文档是**要提交的**，而它里面**真的躺着一个密钥形状的串**。
>
> 所以那是**真命中，不是误报**。
> 🔴 当时的错误直觉是「把 SKILL.md 加进排除名单」—— 而排除名单正是第 4 条刚删掉的东西：
> **一旦能靠加名单让红灯灭掉，这个检查就再也证明不了任何事。**
> 正确的修法是**让文档里别出现密钥形状的串**（打码），而不是让检查别看文档。

三条附带结论：

- **「恰好一条红」才是好证据**。弄坏一项却红一大片，说明检查之间互相串了，定位反而更难。
- **探针不能放 `Temp/`**：那里被 `.gitignore` 拦住，而 A2 只看「会被提交的文件」——
  放那儿**永远扫不到**，测了等于没测。（第一版差点就这么干。）
- **写了文档也要重跑**：这次的红点就是「写完文档没重跑」才出现的（第 5 轮）。
  文档也是要提交的文件，也在扫描范围里。
- 有 FAIL 时**退出码 = 1**（已实测），将来可以直接接进别的脚本。
