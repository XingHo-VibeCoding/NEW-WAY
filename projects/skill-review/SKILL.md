# 简册 · 交工前检查清单（Skill）

> 一句话：这是一份写给 AI 的「作业检查清单」——做新功能前翻出来看，做完逐项打勾，防漏防跑偏。

## 使用方式（调用方法）

1. **动手前**：通读一遍清单，圈出与本次任务相关的条目。
2. **做完后**：逐项检查，在「调用记录」表里记录 ✓ / ✗。
3. 出现 ✗ → 修 → 复查，直到全部 ✓ 才算交工。
4. 每次真实调用都要在文末「调用记录」表里留一行，没有记录 = 没调用过。

## 一、术语与命名（AGENTS.md 附三 · 2）

- [ ] 界面文字、代码注释里模块固定叫「**账簿面**」（底牌页、记一笔）和「**简历面**」（记一条、简历预览），不许换词。
- [ ] 项目名固定写「简册」；英文全称 `Ledger and Career` 只在 README 首次出现。

## 二、示例数据一律假数据（AGENTS.md 附三 · 3）

- [ ] 新增代码、示例、测试里出现的金额、公司名、手机号、身份证、薪资，一律是编造的假数据（如「某某科技」「¥8,000」）。
- [ ] 真实账目、真实简历、个人身份信息不进代码、不进截图。

## 三、零外部依赖（TECH_DESIGN 拍板）

- [ ] 不引 CDN、不引外部字体、不引外部 JS 库；仍是单个 `index.html` 承载。
- [ ] 新增功能用原生 HTML / CSS / JS 实现。

## 四、无障碍基线（2026-09-22 全量体检后确立）

- [ ] 新增按钮键盘能看见焦点：有 `:focus-visible` 描边，不能只写 `:hover`。
- [ ] 触控目标高度 ≥ 24px。
- [ ] 动态提示走 toast 结构：`role="status" aria-live="polite"`。
- [ ] 「选中 / 当前」状态用属性标记（如 `aria-current`、`aria-pressed`），不只靠颜色。
- [ ] 空状态、无结果状态有可读文字提示，不能只靠图标或留白。
- [ ] 系统开「减少动效」（`prefers-reduced-motion`）时，新增动画要关闭。
- [ ] 装用户输入的容器加 `overflow-wrap: anywhere`，防止长英文撑破版面。

## 五、交互反馈（Day 11 口径）

- [ ] 成功、失败都有 toast；失败 toast 要指路下一步（「去哪、做什么」）。
- [ ] 危险操作（删数据、覆盖导入）必须过 `askConfirm` 确认弹层。
- [ ] toast 藏起时要拆掉内部按钮（`.toast-act`），不留看不见但能聚焦的死按钮。

## 六、数据与同步

- [ ] 简历面与账簿面共用经历数据：任何增 / 改 / 删统一走 `syncEntryViews()`，两页一起刷新。
- [ ] 编辑保存不动 `id` 和 `createdAt`，只刷新 `updatedAt`。
- [ ] 列表排序 / 时间段写法复用 `sortEntries` / `entryPeriod`，不另写第二份。

## 七、测试口径

- [ ] 交互类功能至少测三种情况：**正常出结果 / 无结果（空态）/ 清空恢复（回到原始列表）**。
- [ ] 数据列表类功能要能**眼见四态**（Day 13 追加）：加载中 / 正常 / 空 / 出错，四态互斥（同一时刻只露一块）；出错态要有「能恢复」的重试入口，不能只报错不给出路。
- [ ] 用无头探针跑（`Temp/dayXX_selftest.js` 模式），全部通过才算完成。
  - 含 `setTimeout` 延迟的加载态**不能用 `--virtual-time-budget` 测**（虚拟时间会把定时器瞬间推过去，加载态抓不到）；改用「真实时间 + 结果 POST 回信标服务」跑（骨架见本机技能的坑 17）。
